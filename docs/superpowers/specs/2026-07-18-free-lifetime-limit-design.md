# Free tier: 1 lifetime search instead of 5/day

## Контекст и мотивация

После введения платного 24-часового доступа ([2026-07-16-paid-search-pass-design.md](2026-07-16-paid-search-pass-design.md)) бесплатный лимит остаётся 5 поисков в день, что сильно отодвигает момент, когда пользователь вообще видит paywall. Решение: сократить бесплатный лимит до одного поиска за всё время использования бота (не в день, а вообще). После него — всегда платно (150 ⭐ / 24 часа), рекуррентного бесплатного тира больше нет.

## Ключевые решения

- **Лимит**: 1 бесплатный поиск за всё время на пользователя (а не в день).
- **Миграция старых пользователей**: без отдельного шага. Redis-множество `stats:known_users` уже содержит `user_id` каждого, кто хоть раз делал поиск (пополняется в `check_and_increment` через `sadd`, независимо от того, был ли поиск разрешён). Это множество становится источником правды: если `user_id` уже в `stats:known_users` — бесплатный поиск считается использованным. Новые пользователи получают ровно один бесплатный поиск, после которого сами туда попадают (как и сейчас).
- **После истечения купленного 24-часового доступа**: пользователь возвращается в состояние «бесплатный поиск закончился», а не получает новый бесплатный поиск. Бот полностью платный после первого поиска — рекуррентного бесплатного тира нет.
- **Уведомление при трате единственного бесплатного поиска**: сразу после результатов первого (бесплатного) поиска добавляется приписка, честно предупреждающая, что дальше нужно платить.

## Архитектура

### `bot/limits.py`

Переименовать `FREE_DAILY_LIMIT = 5` → `FREE_LIFETIME_SEARCHES = 1`.

**`check_and_increment(user_id)`** — заменить логику на основе `rl:{user_id}:{date}` (счётчик с TTL до полуночи) на проверку членства в `stats:known_users`:

1. Есть активный `premium_until >= today` → `(True, -1)`, без изменений.
2. `user_id` уже есть в `stats:known_users` → `(False, 0)` — бесплатный поиск уже потрачен (когда-либо), пользователь видит paywall.
3. `user_id` отсутствует в `stats:known_users` → это первый поиск в жизни → `(True, 0)`. Пользователь добавляется в `stats:known_users` в рамках этого же вызова (это уже происходит сегодня для статистики — переиспользуем существующий `sadd`).

Статистика (`stats:day:{today}` — `searches`, `active`, `new_users`) собирается независимо от гейтинга, как и сейчас — это метрика вовлечённости, не завязанная на paywall.

**File-fallback (локальная разработка без Redis)** — аналогичная замена: вместо `entry["date"]`/`entry["count"]` — булев флаг `entry["free_used"]`. Если `False`/отсутствует → разрешить и выставить `True`. Если `True` → запретить.

**`get_status(user_id)`** — должен использовать тот же источник правды (`stats:known_users`), иначе `/status` покажет пользователю картину, не совпадающую с реальным допуском в `check_and_increment`. Возвращает одно из:
- `{"premium": True, "premium_until": ..., "remaining": -1}` — без изменений
- `{"premium": False, "premium_until": None, "remaining": 1}` — бесплатный поиск ещё доступен
- `{"premium": False, "premium_until": None, "remaining": 0}` — бесплатный поиск использован

### `bot/main.py`

**Импорт**: `FREE_DAILY_LIMIT` → `FREE_LIFETIME_SEARCHES` везде, где импортируется и используется.

**`_run_search`** ([bot/main.py:778-780](../../../bot/main.py#L778-L780)): условие `if 0 < remaining <= 2: text += t(lang, "searches_left")...` заменяется на `if remaining == 0: text += t(lang, "free_trial_used").format(stars=PAID_SEARCH_STARS)`. Поскольку пост-оплатное продолжение поиска (Task 5 предыдущего фича) всегда передаёт `remaining=-1`, условие `remaining == 0` однозначно означает «это был единственный бесплатный поиск» и никогда не сработает при уже оплаченном безлимите.

**`handle_city`** ([bot/main.py:705-716](../../../bot/main.py#L705-L716)): без структурных изменений — по-прежнему вызывает `check_and_increment`, при `not allowed` показывает paywall-клавиатуру (уже реализовано в предыдущей фиче), при `allowed` вызывает `_run_search(..., remaining)`.

**`rate_limit` текст**: убрать `{limit}` и упоминание «сегодня» — теперь это «бесплатный поиск уже использован», без числа.

**`status_free` текст**: разделить на два сообщения в зависимости от `remaining` (1 или 0) — «есть бесплатный поиск» vs «бесплатный поиск использован, доступ — {stars} ⭐/сутки».

**`cmd_status`** ([bot/main.py:145-151](../../../bot/main.py#L145-L151)): выбор ключа (`status_free_available` / `status_free_used`) на основе `status["remaining"]`.

## Локализация

`bot/messages.py`, все 4 языка (en/ru/he/es):

- `rate_limit` — переписать без `{limit}`/«сегодня», с упоминанием {stars}.
- Новый ключ `free_trial_used` — приписка после результатов единственного бесплатного поиска.
- `status_free` — заменить на `status_free_available` (поиск ещё доступен) и `status_free_used` (уже использован, цена доступа).
- Старый ключ `searches_left` удаляется (заменён на `free_trial_used`), т.к. становится мёртвым кодом.

## Edge cases

- **Пользователь уже в `stats:known_users`, но никогда не покупал доступ** (обычный случай для всех текущих пользователей после деплоя) — сразу видит paywall при следующем поиске. Это ожидаемое поведение перехода на новую модель.
- **Пользователь купил 24-часовой доступ, он истёк** — `premium_until < today`, `user_id` в `stats:known_users` → paywall снова, без нового бесплатного поиска.
- **Гонка двух одновременных первых запросов от одного нового пользователя** (`concurrent_updates(True)` уже используется ботом) — `sadd` в Redis атомарен, поэтому только один из двух конкурентных вызовов получит `added == 1`; оба запроса при этом технически могут пройти проверку `sismember` до того, как другой успеет вызвать `sadd` (TOCTOU), потенциально пропустив оба поиска бесплатно. Это редкий и дешёвый edge case (то же самое было бы возможно и при желании атаковать намеренно), отдельная защита (Redis-транзакция/Lua-скрипт) не требуется для масштаба проекта — соответствует уровню строгости остального кода (`sites_db race condition` уже описан как известное ограничение в NOTES.md).

## Вне скоупа

- Отдельный флаг `free_used` в `users_db` с миграционным скриптом — отклонено в пользу переиспользования `stats:known_users` (см. «Ключевые решения»).
- Изменение цены/длительности платного доступа (150 ⭐ / 24 часа) — не трогаем, это отдельная уже реализованная фича.
- Точная защита от TOCTOU-гонки на первом бесплатном поиске — см. Edge cases, признано неоправданным для масштаба проекта.
